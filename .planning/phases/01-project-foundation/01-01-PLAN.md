   The config MUST preserve ALL existing app.json settings exactly:
   - name: "orion_frontstage_MK-1" (override to "MVR" when APP_VARIANT=production, "MVR (Dev)" otherwise)
   - slug: "orion_frontstage_MK-1"

   Add `extra` field mapping environment variables:
   ```
   extra: {
     supabaseUrl: process.env.EXPO_PUBLIC_SUPABASE_URL,
     supabaseAnonKey: process.env.EXPO_PUBLIC_SUPABASE_ANON_KEY,
     sentryDsn: process.env.EXPO_PUBLIC_SENTRY_DSN,
     posthogApiKey: process.env.EXPO_PUBLIC_POSTHOG_API_KEY,
     eas: {
       projectId: process.env.EAS_PROJECT_ID,
     },
   }
   ```

   Add plugins array preserving existing plugins and adding Sentry:
   ```
   plugins: [
     'expo-router',
     ['expo-splash-screen', { ...existing splash config... }],
     'expo-video',
     ['@sentry/react-native/expo', {
       organization: process.env.SENTRY_ORG,
       project: process.env.SENTRY_PROJECT,
     }],
   ]
   ```

2. Delete `app.json` after creating `app.config.ts`. Expo reads app.config.ts preferentially.

3. Create `constants/config.ts` with type-safe environment variable access:
   ```typescript
   import Constants from 'expo-constants';

   const extra = Constants.expoConfig?.extra;

   export const SUPABASE_URL: string = extra?.supabaseUrl ?? '';
   export const SUPABASE_ANON_KEY: string = extra?.supabaseAnonKey ?? '';
   export const SENTRY_DSN: string = extra?.sentryDsn ?? '';
   export const POSTHOG_API_KEY: string = extra?.posthogApiKey ?? '';
   ```

   Add a validation function that warns (console.warn) if required variables are missing at startup. Do NOT throw — allow development without all services configured. Use `__DEV__` guard so warnings only appear in development.

   Pattern: Early return if empty string, warn with variable name.

   ```json
           "simulator": false
         },
         "channel": "preview",
         "env": {
           "APP_VARIANT": "preview"
         }
       },
       "production": {
         "autoIncrement": true,
         "channel": "production",
         "env": {
           "APP_VARIANT": "production"

       }
     },
     "submit": {
       "production": {
         "ios": {
           "appleId": "REPLACE_WITH_APPLE_ID",
           "ascAppId": "REPLACE_WITH_ASC_APP_ID"
         }
       }
     }
   }
   ```

2. Create `.env.example` documenting ALL required environment variables with comments explaining each:

   ```
   # Supabase (client-safe, embedded in bundle)
   EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

   # Sentry (DSN is client-safe, auth token is build-time only)
   EXPO_PUBLIC_SENTRY_DSN=https://your-dsn@sentry.io/project-id
   SENTRY_ORG=your-org-slug
   SENTRY_PROJECT=your-project-slug
   # SENTRY_AUTH_TOKEN - Add as EAS Secret, NEVER in .env
   # Run: eas secret:create --name SENTRY_AUTH_TOKEN --value YOUR_TOKEN

   # PostHog (client-safe)
   EXPO_PUBLIC_POSTHOG_API_KEY=phc_your-api-key

   # EAS Build
   EAS_PROJECT_ID=your-eas-project-id
   # EXPO_TOKEN - Add as GitHub Secret for CI/CD
   # Generate at: https://expo.dev/accounts/[account]/settings/access-tokens

   # App variant (set automatically by EAS Build profiles)
   # APP_VARIANT=development|preview|production
   ```

3. Verify `.gitignore` already contains `.env*.local` (it does). No changes needed to .gitignore.

4. Create `.github/workflows/eas-build.yml`:

   ```yaml
   name: EAS Build

   on:
     push:
       branches: [main]
     workflow_dispatch:

   jobs:
     build:
       name: Build and Submit to TestFlight
       runs-on: ubuntu-latest
       steps:
         - name: Checkout
           uses: actions/checkout@v4

         - name: Setup Node.js
           uses: actions/setup-node@v4
           with:
             node-version: 18
             cache: npm

         - name: Setup EAS
           uses: expo/expo-github-action@v8
           with:
             eas-version: latest
             token: ${{ secrets.EXPO_TOKEN }}

         - name: Install dependencies
           run: npm ci

         - name: Build iOS for TestFlight
           run: eas build --platform ios --profile production --non-interactive --auto-submit
           env:
             EXPO_PUBLIC_SUPABASE_URL: ${{ secrets.EXPO_PUBLIC_SUPABASE_URL }}
             EXPO_PUBLIC_SUPABASE_ANON_KEY: ${{ secrets.EXPO_PUBLIC_SUPABASE_ANON_KEY }}
             EXPO_PUBLIC_SENTRY_DSN: ${{ secrets.EXPO_PUBLIC_SENTRY_DSN }}
             EXPO_PUBLIC_POSTHOG_API_KEY: ${{ secrets.EXPO_PUBLIC_POSTHOG_API_KEY }}
             SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
   ```

   Include `workflow_dispatch` trigger so builds can be run manually during early development when automated builds per-merge may not be desired (per research open question about EAS free tier limits).
  </action>
