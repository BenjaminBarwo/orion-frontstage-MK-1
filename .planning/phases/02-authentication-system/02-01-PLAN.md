**Step 7: Create lib/auth-context.tsx** with SessionProvider:
- Create `AuthContextType` interface with: `session: Session | null`, `isLoading: boolean`, `signIn(email, password): Promise<void>`, `signUp(email, password): Promise<void>`, `signOut(): Promise<void>`, `signInWithGoogle(): Promise<void>`, `signInWithApple(): Promise<void>`
- Create `AuthContext` with `createContext<AuthContextType | undefined>(undefined)`
- In `SessionProvider`:
  - `useState` for session and isLoading
  - `useEffect` to call `supabase.auth.getSession()` on mount, set session, set isLoading false
  - `useEffect` to subscribe to `supabase.auth.onAuthStateChange`, update session state, unsubscribe on cleanup
  - `signIn`: call `supabase.auth.signInWithPassword({ email, password })`, throw on error
  - `signUp`: call `supabase.auth.signUp({ email, password })`, throw on error
  - `signOut`: call `supabase.auth.signOut()`, throw on error
  - `signInWithApple`: import `expo-apple-authentication`, request email + full name scopes, get `identityToken`, call `supabase.auth.signInWithIdToken({ provider: 'apple', token })`, throw on error. Wrap in try/catch — if `AppleAuthentication.AppleAuthenticationCredentialState` indicates cancelled, silently return.
  - `signInWithGoogle`: import `GoogleSignin` from `@react-native-google-signin/google-signin`, configure with `webClientId` from `GOOGLE_WEB_CLIENT_ID`, call `hasPlayServices()`, `signIn()`, extract `idToken` from `userInfo.data`, call `supabase.auth.signInWithIdToken({ provider: 'google', token })`, throw on error
  - Return `<AuthContext.Provider value={...}>{children}</AuthContext.Provider>`
- Export `useAuth()` hook: `useContext(AuthContext)`, throw if undefined ("useAuth must be used within SessionProvider")

**Modify app/_layout.tsx** to add authentication routing:

1. Import `SessionProvider` and `useAuth` from `@/lib/auth-context`
2. Import `Toast` from `react-native-toast-message`
3. Import `SplashScreen` from `expo-router` and call `SplashScreen.preventAutoHideAsync()` at module level

4. **Restructure `RootLayout`** function:
   - Wrap everything in `SessionProvider` as the outermost provider (inside Sentry.wrap, outside PostHogProvider)
   - Create a separate inner component `RootLayoutNav` that calls `useAuth()` to get `session` and `isLoading`
   - In `RootLayoutNav`:
     - Call `SplashScreen.hideAsync()` in useEffect when `isLoading` becomes false
     - While `isLoading` is true, return null (splash screen stays visible)
     - Use Expo Router's redirect pattern: if no session, show (auth) screens; if session exists, show (tabs) + welcome
     - Use `<Stack>` with conditional screen registration:
       ```
       <Stack screenOptions={{ headerShown: false }}>
         <Stack.Screen name="(auth)" options={{ headerShown: false }} />
         <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
         <Stack.Screen name="welcome" options={{ presentation: 'modal', headerShown: false, gestureEnabled: false }} />
       </Stack>
       ```
     - Use `<Redirect href="/(auth)/sign-up" />` when no session, and `<Redirect href="/(tabs)" />` when session exists
     - NOTE: Expo Router handles this with the `useRootNavigationState` and redirect pattern from docs. The key is: register all screens but use `<Redirect>` to control navigation based on auth state.

5. **Keep existing providers** in the right nesting order: `Sentry.wrap(RootLayout)` → `SessionProvider` → `PostHogProvider` (conditional) → `ThemeProvider` → `Stack`

6. **Add `<Toast />` as the very last child** inside the root return, AFTER the Stack and StatusBar. Must be the last element rendered so toasts appear above everything.

7. Keep existing Sentry navigation integration (navigationRef + sentryNavigationIntegration).

8. Keep `unstable_settings` with anchor as `(tabs)`.

IMPORTANT: Do NOT use Stack.Protected — research shows the redirect pattern is more reliable with Expo Router. Use `<Redirect>` component conditionally based on `session` state within the layout component.

IMPORTANT: The gestureEnabled: false on welcome screen prevents dismissing the welcome card via swipe (user must tap "Get Started").
