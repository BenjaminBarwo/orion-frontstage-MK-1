**Step 1: Create Photo screen (Step 4)**

Create `app/(onboarding)/photo.tsx`:

Heading: "Show your face" or similar (discretion). Subtext: "Clients trust pros they can see" in muted.

Center: Large circular photo display using `ProfilePhotoDisplay` component from `@/components/profile/profile-photo-display` at 180px size. If `formData.photoUri` is null, show the initials placeholder (using formData.firstName and formData.lastName for initials).

Below photo: Two action buttons side by side or stacked:
- "Choose from Library" — calls `pickProfilePhoto()` from `@/components/profile/profile-photo-picker`
- "Take Photo" — calls `takeProfilePhoto()` from same module

On success: `updateFormData({ photoUri: resultUri })`. On cancel: do nothing. On permission error: show toast error via `showAuthError` from `@/lib/auth-toast`.

Both functions return null if cancelled (handle gracefully). Both throw if permission denied (catch and show toast).

Continue button: Enabled only when `formData.photoUri !== null` (photo required, no skip). On press: `router.push('/(onboarding)/bio')`.

**Step 2: Create Bio screen (Step 5)**

Create `app/(onboarding)/bio.tsx`:

Heading: "Tell pros about you" or similar (discretion). Subtext: "What makes you the right pro?" in muted.

Multi-line TextInput: `maxLength: 300`, `multiline: true`, `numberOfLines: 5`, `textAlignVertical: 'top'`, placeholder "Share your experience, specialties, and what sets you apart...", dark input styling, height ~140px.

**Step 3: Create Review screen (Step 6)**

Create `app/(onboarding)/review.tsx`:

Heading: "Review your profile" — same styling. Subtext: "Make sure everything looks right" in muted.

Display profile summary in a card-like layout:
- Circular profile photo at top (120px) using `ProfilePhotoDisplay`
- Display name: `{firstName} {lastName}` in white, 22px bold
- Role badge: role label text in gold, or small pill/badge
- Location: zip code with location pin icon (Ionicons `location-outline`)
- Bio: full bio text in muted/light gray, wrapped

Each section is tappable — on tap, navigate back to that step using `router.push('/(onboarding)/role')` etc., so the pro can edit individual fields. Show a subtle edit icon (Ionicons `pencil-outline`) next to each section.

"Complete Profile" button at bottom: Gold gradient button (same as Continue buttons).

On press:
1. Disable button, show `ActivityIndicator` in button
2. Call `saveProfile(session.user.id, { firstName: formData.firstName, lastName: formData.lastName, role: formData.role!, zipCode: formData.zipCode, bio: formData.bio, photoUri: formData.photoUri! })` from `@/lib/profile-service`
3. On success: Show success toast "Profile created!", then `router.replace('/(tabs)')` to enter main app
4. On error: Show error toast with message, re-enable button

Access session via `useAuth()` from `@/lib/auth-context`.

**Step 4: Update root layout for profile completeness gate**

Modify `app/_layout.tsx`:

In `RootLayoutNav`:
1. Add state: `const [profileComplete, setProfileComplete] = useState<boolean | null>(null)` (null = loading)
2. Add effect: When session exists and isLoading is false, call `getProfile(session.user.id)` from `@/lib/profile-service`. If profile exists and `onboarding_completed === true`, set `profileComplete(true)`. Otherwise set `profileComplete(false)`.
3. Keep splash screen visible while `profileComplete === null` (still determining). Update the splash hide condition to: `!isLoading && profileComplete !== null`.
4. Register `(onboarding)` screen in the Stack:
   ```
   <Stack.Screen
     name="(onboarding)"
     options={{ headerShown: false }}
     redirect={!session || profileComplete !== false}
   />
   ```
5. Update `(tabs)` redirect: `redirect={!session || !profileComplete}`
6. After profile save completes (in review screen), the profile is marked complete in DB. When navigating to `/(tabs)`, the root layout will re-check and find `onboarding_completed: true`.

Also handle the edge case: existing users who sign in but have incomplete profiles should also be redirected to onboarding. The `profileComplete` check handles this.

Add a `refreshProfile` or simply refetch on focus to handle the transition from onboarding to tabs.
