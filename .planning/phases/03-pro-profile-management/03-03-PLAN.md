Create `app/(tabs)/edit-profile.tsx`:

A screen that allows editing all profile fields. Accessed from Profile tab's edit button.

Dark background, SafeAreaView. Custom header bar at top with:
- Back arrow (Ionicons `arrow-back`) on left — `router.back()`
- "Edit Profile" title in white, centered
- "Save" text button on right in gold — triggers save

Layout (ScrollView + KeyboardAvoidingView):

**Photo section** (top, centered):
- Current profile photo in 120px circle using ProfilePhotoDisplay
- "Change Photo" text below in gold — on tap, show ActionSheet (Alert.alert with options: "Choose from Library", "Take Photo", "Cancel") then call `pickProfilePhoto()` or `takeProfilePhoto()`. Update local state with new URI.

**Form fields:**
Each field in a labeled section with label text in muted, input below:

- **First Name:** TextInput, pre-filled from current profile, dark input styling (same as onboarding)
- **Last Name:** TextInput, same
- **Role:** Tappable field showing current role label. On tap, show a modal/bottom sheet or navigate to role picker. For simplicity, use the same RoleCard list in a scrollable section. The 5 cards appear inline, tappable, with gold gradient border on current selection.
- **Zip Code:** TextInput, keyboardType number-pad, maxLength 5, Houston validation on save
- **Bio:** Multi-line TextInput, maxLength 300, with character counter

**Save flow:**
On "Save" press:
1. Validate all fields (name 2-50 chars, zip is Houston, bio 1-300)
2. If new photo was picked (photoUri differs from current avatar_url), call `uploadProfilePhoto(newPhotoUri, userId)` first
3. Call `updateProfile(userId, { first_name, last_name, display_name, role_category, zip_code, bio, avatar_url (if changed) })` from `@/lib/profile-service`
4. On success: toast "Profile updated!", `router.back()`
5. On error: toast error message
6. Disable Save button and show ActivityIndicator during save

**State management:**
- Load current profile on mount via `getProfile(session.user.id)`
- Store editable fields in local state (useState for each field or a single form object)
- Track if photo was changed separately (compare local photoUri to loaded avatar_url)

**Validation:**
- Use same Zod schemas from `@/lib/validation/profile-schemas` for field validation
- Show inline errors on save attempt if validation fails
